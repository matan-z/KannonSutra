# 開発ログ — 観音経 暗記道場

Claude Code（Claude）とのやりとりの記録。音声生成は Codex が別に担当しており、その作業内容はこのログには含まれていない（Claude が確認した範囲だけを書く）。

---

## 2026-10-17

### 1. 構成の検討と初版の作成
**依頼**: 観音経を楽しく暗記して、ひとりで読経できるようになる HTML ゲームを作りたい。まずは GUI だけにし、音声（別の AI で生成）と 3D（Blender と Codex で作る）は後から入れる。

**決めたこと**
| 項目 | 決定 |
|---|---|
| 範囲 | 世尊偈（104句・5字1句） |
| 読み | 一般的な呉音読み（データ側で差し替えられるようにする） |
| 技術 | Vanilla HTML/CSS/JS（ES Modules）、ビルド不要、外部ライブラリなし |
| 方針 | データ・ゲームの仕組み・描画・音声を分けておき、音声と 3D を後から差し込める作りにする |

**作ったもの**
- 経文データ（[sekai-ge.js](../js/data/sekai-ge.js)）: 104句を、漢字・1字ずつの読み・句番号・段（13段×8句）で持つ
- 修行モード5つ: 経本・穴埋め・次の句は？・並べ替え・ひとり読経
- 記憶度: 句ごとに0〜5で記録し、3以上を「覚えた」とする。段の全句が3以上で「成就」し、次の段が開く
- 演出: 正解で花びら、連続正解の表示、ホームの108玉の数珠と開いていく蓮、成就したときの満開の蓮
- 設定: ルビ、縦書き／横書き、文字サイズ、全段解放、記録リセット
- 音声と描画を差し替えるための入口: [audioService.js](../js/audio/audioService.js)、[visual/index.js](../js/visual/index.js)

**確認**: ヘッドレス Chrome で全モードを自動で通しプレイし、エラーなし。
- 縦書きの経本で、1列に句が詰まりすぎる問題があった。1行（縦書きでは1列）2句の経本の体裁に直した
- 並べ替えで、スマホでは札が画面外に押し出されていた。札を小さくして直した

### 2. ひとり読経の答えにルビを表示
**依頼**: ひとり読経で答えを見たときにルビを付けてほしい。
**原因**: 経本モードの「ルビ」ボタンでルビをオフにすると、それがひとり読経にも効いていた。
**対応**: 答えを見た句だけは、ルビ設定がオフでも読みを表示するようにした。伏せている句には読みを出さない。

### 3. 現代語訳を覚えられるようにする
**依頼**: 現代語訳も覚えられるようにしたい。
**対応**
- 104句すべてに、句ごとの現代語訳（意訳）を付けた。偈の4句を続けて読むと一文になる
- 新モード「⑤ 意味あわせ」を追加: 句から訳、訳から句を交互に4択で答える。ひとり読経は⑥に繰り下げ
- 訳の表示: 経本では読んでいる偈の訳、ひとり読経では答えを見たときの訳、段の画面では一覧に訳を出す
- 意味の記憶度は、読みとは別に記録する（キーは `m1`, `m2`…）。段の成就は読みだけで判定する
- 設定に「現代語訳を表示」を追加

**メモ**: 作業中に、Codex が経本モード（learn.js）と音声まわりを音声対応に書き換えていたことに気付いた。その版を残したまま訳の表示を組み込んだ。

### 4. Codex の音声生成の確認（レビュー）
**依頼**: Codex で音声を生成して組み込んだので確認してほしい。

**問題なかった点**: ゆっくり版と通し読み版の2種類が104句そろっており、区間の重なりや欠けはない。経文を書き換えると、ずれた範囲の音声は自動で使えなくなる。生成スクリプトのテストは5件とも成功。ブラウザでも再生でき、文字の強調も音声に合わせて進んだ。

**指摘した点**
1. 誤読が3句あった（起動中の VOICEVOX で全句の発音を確認した）
   - 9「弘誓深如海」・13「我為汝略説」: 「にょ」が「ニ・ヨ」に分かれて読まれる
   - 82「慧日破諸闇」: 「は」が助詞の「ワ」として読まれる
   - カタカナで渡すと上の3句は直るが、今度は1・20・38・73・84 で「ミョウ→ミヨウ」などの別の誤読が出る
2. 通し読み版で、文字の強調が一部飛ぶ（第一段の40字中4字）。再生位置の通知が約0.25秒おきで粗いため
3. どこからも使われていない重複ファイルなど、約49MB の不要分がある

**結果**: Codex が参考の読経音声をもとに音程の不自然さを直している最中のため、**音声まわりの修正は保留**となった。

### 5. 結び（長行）の追加
**依頼**: 「是故応頂礼」のあとの部分がないので追加してほしい。
**対応**
- 「爾時持地菩薩 … 阿耨多羅三藐三菩提心」の15句を、第十四段「結び（持地菩薩）」（105〜119句）として追加した。読みと現代語訳も付けた。全体は119句、14段になった
- 音声生成スクリプトが読む `ROWS`（偈104句）とは分けて、`PROSE_ROWS` に置いた。Codex の作業に影響しないようにするため
- 経本の訳表示は「結び（1）〜（3）」の文ごとにした。縦書きパネルは縦にもスクロールできるようにした

**影響**: 結びの音声がないため、ホームの「通しで読む」（全119句）では音声が選べなくなった。

**照合が必要な読み**: 105句目の「爾時（にじ）」、117句目の「衆中（しゅちゅう／しゅうちゅう）」。

### 6. 経題の追加
**依頼**: 第一段の前に「妙法蓮華経観世音菩薩普門品第二十五偈」を加えてほしい。
**対応**
- 経題（読みは「みょうほうれんげきょう かんぜおんぼさつ ふもんぼん だいにじゅうごげ」）を、番号のない見出しとして追加した（データでは `SUTRA_TITLE`）
- 表示する場所: 第一段と通し読経の経本・ひとり読経の先頭（朱色・ルビ付き）、第一段の画面、ホームの小見出し

**判断**: 句として足すと句番号が1つずつずれ、保存済みの記憶度や音声との対応が崩れる。そのため、経本での強調・ゲーム・記憶度の対象外にした。対象にする場合は、音声作業が終わってから行う。

### 7. 未解放の段を鍵マークに
**依頼**: 「未解放」の文字を鍵マークにしてほしい。
**対応**: ホームの段一覧を鍵のアイコンにした（画面読み上げでは「未解放」と読まれる）。

### 10. GitHub へのアップロード
**依頼**: いまのファイルを GitHub の `matan-z/KannonSutra` に上げてほしい。
**対応**
- フォルダは Git の管理下になかった（空の `.git` があるだけ）ので、新しく管理を始めた。GitHub 側に最初からあった LICENSE（MIT）のコミットの上に重ねた
- 音声は 665MB あり、ほとんどが作業途中の中間ファイルだった。`.gitignore` で、アプリが読み込む句ごとの mp3（manifest.json が参照する 240 個）だけを上げるようにした。wav・バックアップ・試聴用・古い manifest は上げていない（手元には残っている）

### 11. 公開に向けた整理と、セキュリティチェック
**依頼**: 参考動画の記述・その削除のコミット・使っていない音声を GitHub から消すこと、アップロードしたファイルのセキュリティチェック。
**対応**
- README と音声の CREDITS.txt から、参考動画についての記述（人名・URL・区間）を消した
- のちに、スクリプト・manifest.json・音程データ・このログに残っていた参考動画の URL も消した。スクリプトは URL を「前回と同じ参考音声か」の比較に使っているため、スクリプトと manifest.json には同じ置き換え文字列（`local-reference-recording`）を入れた。テスト（Python 13件・JavaScript 2件）は通過
- アプリが読み込まない通し・経題の mp3（8本）を GitHub から外した（手元には残っている）
- 会話ログ（docs/conversation-logs/）を GitHub から外した（手元には残っている）
- コミットの作者欄に個人の Gmail アドレスが入っていたため、GitHub の非公開用アドレス（noreply）に差し替えた。このリポジトリの Git 設定も同じアドレスにした
- `.gitignore` に、秘密情報（`.env`・鍵ファイルなど）・仮想環境・エディタや AI ツールの設定などの予防の除外を足した
- README の末尾に「ライセンス」を足し、音声は MIT の対象外で VOICEVOX の利用規約と音声ライブラリの条件に従うと明記した
- 削除の跡を残さないよう、これらの変更はすべて最初のコミットにまとめて force push した。履歴は「Initial commit」と「観音経 暗記道場（2D版）を追加」の2件

**チェック結果**: 秘密情報（API キー・パスワード・秘密鍵）はなし。アプリはブラウザ内（localStorage）にだけ保存し、外部へ送信しない。HTML に外部の文字列を埋め込む箇所もない。音声生成スクリプトは、コマンドの差し込みができない書き方で、VOICEVOX への接続先も localhost に限られている。mp3 の埋め込み情報は、話者のクレジットと句の名前だけ。

### 12. リポジトリの公開と Vercel での公開
- ユーザーが GitHub のリポジトリを公開（public）にした
- GitHub Pages ではなく Vercel で公開した（ユーザーが Web 画面で操作）。公開 URL は https://kannonsutra.vercel.app
- 本番の URL をスマホ幅（390px）で自動操作して確認した。全10画面でエラーも横はみ出しもなく、音声2種類（ゆっくり・通し読み）も読み込めた。favicon がない警告が1件だけ出た
- LINE で知らせるための紹介文を用意した

### 13. ほかの公開リポジトリの整理
IT 系の友達に GitHub アカウントを見てもらう前に、ほかの公開リポジトリも確認した。
- **KoreDeFilter**: 誤って追加したノートブックのコミットと、それを消したコミットの2件を履歴から消した。中身は消す前と同じ。2021年の4件のコミットの作者欄に別の個人の Gmail アドレスが入っていたので、非公開用アドレスに書き換えた。Excel のアドイン本体も含め、ファイルの中身には個人情報なし
- **classic-tennis・html-test**: 作者欄はもとから非公開用アドレスで、ファイルにも個人情報なし

これで、公開している4つのリポジトリすべてで、コミットに個人のメールアドレスが残っていない。

**保留にした理由**: `operation-log.md` には、GitHub に上げていないファイルへのリンクが4つある（会話ログ2か所、音声のバックアップと復元記録）。そのまま上げると GitHub 上でリンクが開かない。「このまま上げる」か「リンクを普通の文に直してから上げる」かは、ユーザーが後で決める。それまで2つとも GitHub には上げない。

**Codex のスマホ確認でわかった問題（未修正）**

- 「戻る」の高さ（約38px）と並べ替えの札の高さ（約41px）がやや小さく、タップしにくいことがある
- 縦書きの経文パネルが横にスクロールできることに気づきにくい。狭い画面や横向きでは、パネル内で上下のスクロールも必要
